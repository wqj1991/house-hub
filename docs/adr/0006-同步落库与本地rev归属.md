# 0006 同步落库与本地 rev 归属

- 状态：已采纳（2026-11-13）
- 上下文：P2 同步的最后一环是「pull 到的行怎么落库」。服务器按 rev 升序发页，客户端要能断点续拉，还得知道「我拉到哪儿了」。

## 决定

### 1. 本地 rev 存 `sync_meta`，不进 `app_setting`

`app_setting` 是会同步的，rev 一旦进去就成了两端互相覆盖的对象——A 拉到 10877 写回服务器，B 拉到 10880 又盖回去，永远收敛不了。rev 是**设备本地游标**，不是业务数据。

因此：`create table if not exists sync_meta(key text primary key, value text not null)`，key 固定为 `rev`，随迁移 `0002_sync_meta.sql` 建。服务器侧的 `sync_counter` 是全局发号器，两边各自独立。

### 2. `apply_sync_page` 单事务，按 uid 命中

一个页面一个事务：命中原行则 update 全部列并写 `rev = page.rev`、`deleted_at = null`；没命中则 insert，跳过 `id` / `uid` 的自增与默认值；随后按 `deleted` 集合打墓碑；最后写 rev。任何一步失败整页回滚，下次从旧 rev 重来——同步必须可重放。

跳过自增的理由：`id` 是本地句柄，两端的 id 空间不同源；对外一律用 `uid`。

### 3. Web 端不跑 SQLite，pull 的页落 IndexedDB 快照

浏览器里塞 30 MB SQLite 要为 OPFS 兼容性还债（见 §5 的取舍）。Web 的 `RemoteRepo.sync()` 是 push 完 pull 最多 20 页，每页 `snapshot.savePage` 写进 IDB（库 `house-snapshot`，store `rows`，`keyPath = "table:uid"`），`listShortlist` / `listQuality` / `listChecks` / `getSettings` 全部从快照读。

快照是**只读副本**：写操作一律进 outbox，不写快照。这样「界面看到的就是服务器上一次说的」不会被本地半成品污染。

### 4. 分页循环必须有反截断守卫

服务器按 `rev > since order by rev asc limit 501` 截断全表同 rev 的极端情况。客户端循环写成：

```ts
if (!body.more || body.rev <= before) break;
```

少了后半句，收到一页「more: true 但 rev 没前进」就会原地空转到 20 页上限。

### 5. schema 漂移用脚本守，不靠人眼

本地 `apps/shell/src-tauri/src/schema.sql` + migrations 与 `services/api/src/migrations` 是两份真值，漂移不会报错、只会让同步悄悄丢列。`scripts/schema-check.mjs` 逐字符解析建表体比对，缺表/缺列退出码 1；服务器独有表在 `SERVER_ONLY` 里写明理由（`sync_counter` / `pairing_code` / `device` / `job` / `rule_set` / `geo_cache`），加表前先问「客户端同步它吗」。

## 后果

- 本地有 13 个 Rust 命令可用（db_status / sync_rev / apply_sync_page / search_communities / get_community / list_shortlist / add_shortlist / remove_shortlist / get_settings / put_setting / list_rules 等），`list_quality` 等 12 个仍在 `lib.rs` 末尾的 `TODO(P3)` 里。
- 规则 hash 走 `list_rules` 的 FNV-1a 64（`version = read_rev`），`packages/data/src/local.ts` 的 `TODO(P5)` 已消。
- `pnpm check:schema` 进 CI 之前，至少提交前跑一次。

## 被取代 / 待补

- `packages/data/src/sync.ts` 的 `MAX_PAGES = 20` 是经验值：3000 小区在 500/页 下约 6 页，留 3 倍余量。数据量涨到 1 万小区以上要重估。
- Web 端尚无「待同步 N 条」的界面（outbox 有数据但不展示），等 P5 收尾。
