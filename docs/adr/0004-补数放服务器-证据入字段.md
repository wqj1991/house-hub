# 补数放服务器，值必须带证据

> 迁入自 `D:\repos\house\docs\adr\0004-补数放服务器-证据入字段.md`（2026-11-13）。本仓库为真值；house 仓库的同名副本待其退役时删除。

小区品质分有 25 项，其中 17 项（容积率、物业费、业委会、维权史…）不在任何开放数据里，只能从公开页面里读；而安居客 / 21 世纪 / 5i5j 的反爬让「在 app 里现场抓」既不稳定也没法热修。决定：**抓取与补数放在服务器上的 Python 小服务（`server/house_service/app.py`）**，app 只在需要时调它一次；高德能实测的用高德，其余交给模型，但**每个值都必须带 `evidence`，没有依据就不写**，`source` 与 `confidence` 一起落到 `community_quality`，页面照实显示「未核」。

考虑过的选项：

- **app 内直连反爬源**：出口 IP 一变就废，规则一改要发版，且 `reqwest` + 各站解析会把前端拆成第二个爬虫工程。
- **只靠模型凭记忆填**：24 项能一次填满、看着很漂亮，但错值与真值混在一起无法分辨——本项目要的是「能拿去跟中介对账的数」，不是填满的表。
- **只做高德**：那 17 项永远是空，品质分只剩「配套 + 交通」两维，7 个维度的权重全废。

代价：多了一个要维护的服务（Python 3.6、systemd、nginx 前缀、token），以及一条「模型可能编」的风险——用 evidence 必填 + 置信度上限 0.9 + 页面公示来源来对冲。
