# spec · 城六区外选房台（移动端 UI 主题）

> 三个方向的共同输入。只写「要说什么」，不写「长什么样」。数据为示例，字段与口径全部来自 docs/DESIGN.md。

## 产品
自用的北京购房决策 App。夫妻两人家庭，候选片区锁在北京城六区之外（通州 / 大兴 / 昌平，房山试点），不含环京。
它不是房源电商，是**决策台**：先把不可能的通勤剔掉，再在剩下的里挑小区，最后算钱。

## 使用者与场景
- 使用者：购房的夫妻两人，手机为主，晚上/通勤路上刷，决策周期数月，会反复回看同一个小区。
- 场景特征：单手、暗光（晚上躺床上）、信息密集、需要「为什么它被排在这里」可追溯。
- 情感基调：可信、不推销、能读下去。不要购房电商的催促感，也不要图表仪表盘的炫技感。

## 核心信息（分点）
1. **硬筛**：每人每模式单程 ≤90 分钟才进主榜；>80 分钟标黄。
2. **两个人并行**：老公（施耐德，大兴凉水河二街 2 号，08:00 到岗，有班车/电动车/驾车）；老婆（环球贸易中心 D 座，09:00 到岗，只有公共交通）。两条通勤不能合成一个平均分。
3. **口径差**：德茂地铁站 74 分钟 vs 德茂佳苑小区 88 分钟——同一个「德茂」差 14 分钟。先片区收敛，再小区精选。
4. **积分只做前置校验**：老公申报 3 分/年（cap 12），老婆 2 分/年（cap 6），自有住所 +0.5 分/年；城六区外是平坦的，所以不进排序。两数并列显示，不合并。
5. **资格是门槛不是分数**：通州双限，打「购房资格未核实」红标——红标要压过好看的数字。
6. **两条正交轴**：通勤分与品质分默认不合成总分，并排给出，人说哪条重要。
7. **可追溯**：品质 25 项（权重合计 78），每项都要能点开看到「字段值 + 来源 + 抓取时间」。
8. **钱**：挂牌 ≠ 成交；议价空间 = 挂牌 − 成交；只有单价时总价不可推（需面积假设）。房屋打分 55% + 小区 45%。
9. **时间**：班车车程是「到岗 − 发车」从时刻表减出来的，不是按距离算的。

## 输出格式与尺寸（三版统一）
- 移动端 App 原型：单机 390 × 844（视口 390），每版 5 屏，平铺在展示板上。
- 展示板：1440 × 约 1100，横向。
- 每屏可交互：底部 tab 真正切换 5 屏；至少一处「展开细节」（品质分项 / 时刻倒推 / 口径切换）。
- 底部 tab 5 项：概览 / 通勤 / 小区 / 待选 / 算钱；触控目标 ≥44px，正文 ≥14px，标签 ≥12px，正文对比 ≥4.5:1。

## 已知约束
- 无 logo、无 VI、无品牌色、无照片素材 → 主角只能由「数据图形 / 刻度 / 表格 / 程序化材质」承担。
- 不得与现有「悬浮纸 Floating Paper」主题同类（indigo 277 色阶、26px 圆角、玻璃三档、三栏外壳）。
- 不出现模板装饰：标题上全大写小标签、01/02/03 伪序列、按钮尾巴 →、紫渐变、emoji 图标、左彩条圆角卡。

## 图片需求
无。全部用 CSS/SVG 程序化生成：量尺刻度、时刻栅格、等高/地块色块、印章。
